# credit-conserver

**Owner:** thesuperRL
**Platform:** GitHub
**Nature:** A GitHub Actions bot that consumes Anthropic API credits before they expire by automatically triaging GitHub and Codeberg issues: it generates detailed implementation plans with Claude Sonnet, creates WIP draft PRs with kernel-style commit messages generated by Claude Haiku, and handles reviewer change requests on existing PRs before processing new issues.
**Language(s):** Python
**Active period:** 2026-07-26 - 2026-07-27
**Fork of:** Original

## Design Decisions

- Dual-model strategy: expensive `claude-sonnet-4-20250514` for implementation plans, cheap `claude-3-5-haiku-20241022` for kernel-style commit message generation. Reduces credit spend on boilerplate.
- Credit tracking is percentage-based: the GitHub Actions trigger accepts a "use X% of weekly credits" input, and `credit_tracker.py` monitors cumulative input+output tokens and stops gracefully when the cap is reached.
- Priority queue: before processing any new issues, checks all open WIP PRs for review comments containing keywords like "change request", "please update", "needs revision". If found, regenerates the implementation plan and pushes a revised commit to that branch.
- Parallel repo processing via `ThreadPoolExecutor` with a configurable `max_parallel_repos` (default 5). Each repo runs independently; credit exhaustion in one thread stops all via shared state.
- Abstract `GitPlatform` interface in `git_platform.py` with separate implementations for GitHub (PyGithub) and Codeberg (REST API via `requests`). `platform_manager.py` dispatches to the right implementation based on a `github:` or `codeberg:` prefix in the config.
- PR format follows Linux kernel conventions: commit subject is `subsystem: brief description`; PR title is `WIP: subsystem: description`; PR body includes a summary of key design decisions, a link to the full plan markdown, and an attribution footer crediting the tool.
- Config loaded from `config.yml` with environment variable overrides. API tokens are never in config; they come from GitHub Actions secrets.
- The first PR in the repo (`autoresearch/session-20260726`) was itself generated by credit-conserver acting on its own repo, demonstrating self-referential use.
