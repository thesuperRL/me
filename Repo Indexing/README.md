# Repo Indexing

This folder holds deep-dive notes on individual projects and roles. The writing assistant, resume builder, and event interview skills all read these files to ground essays and bullets in accurate technical detail rather than memory.

---

## Convention

One file per project or role. Filename matches the project slug used in skill mappings.

### What to put in each file

- What you built and why
- Key design decisions and the tradeoffs they resolved
- Specific commits, PRs, or technical moments worth referencing in writing
- Accurate scope (users, team size, your ownership vs. others')
- What NOT to overclaim

### Example structure

```
# Project Name

## What It Is
[One paragraph: what this is and what it does.]

## Your Contribution
[What you specifically owned. Be precise about scope.]

## Key Technical Decisions
[Decisions worth citing in essays or bullets. Include why you made them.]

## Specific Moments
[Commits, incidents, design reviews, or inflection points useful for storytelling.]

## Accurate Framing
[How to present this accurately. What not to inflate.]
```

---

## Connecting files to skills

In the `skills/` files, update the Repo Indexing mapping table to point each project slug at the right file. The skills use that mapping to know which file to read for a given role or project.
